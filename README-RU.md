# vpngate

## 1. Статус проекта

**Эта версия проекта устарела.** В дальнейшем проект планируется переработать в распределённую L3 VPN-сеть.

### Известные проблемы совместимости OpenVPN

В ветке Alpine Linux 3.23 используется OpenVPN 2.6. В частности, актуальный пакет для Alpine 3.23 — OpenVPN 2.6.23. Эта версия позволяет одновременно использовать конфигурации `strong` и `compat`.

В OpenVPN 2.6.20 присутствовали проблемы безопасности при использовании `tls-crypt-v2`, в том числе утечки памяти при обработке клиентских ключей, способные привести к исчерпанию памяти и аварийному завершению сервера. Исправления вошли в OpenVPN 2.6.21. Поэтому для конфигурации `strong` следует использовать более новую исправленную версию, например 2.6.23.

Другая проблема совместимости появилась в OpenVPN 2.7.6. В этой версии была ужесточена проверка первого пакета управляющего канала `HARD_RESET`: сервер принимает его только с нулевым `packet ID`. Встроенный клиент старых версий MikroTik RouterOS v6 отправляет первый пакет с `packet ID = 1`, поэтому соединение не устанавливается.

Таким образом, выбор версии OpenVPN зависит от необходимости поддержки старых клиентов MikroTik:

| Версия | `strong` | `compat` |
|---|---|---|
| OpenVPN 2.6.20 | Не рекомендуется из-за известных проблем безопасности | Совместим |
| OpenVPN 2.6.21–2.6.23 | Совместим | Совместим |
| OpenVPN 2.7.6 | Совместим | Несовместим со старыми MikroTik RouterOS v6 |

Оба варианта OpenVPN могут использоваться отдельно и в сочетании с IPsec-сервером.

## 2. Назначение проекта

`vpngate` предназначен для объединения удалённых устройств, не имеющих собственных доступных из интернета IP-адресов, в общую VPN-сеть.

Это позволяет централизованно получать доступ к таким устройствам. Например, через VPN-сервер можно объединить рабочие и домашние компьютеры, компьютеры друзей, маршрутизаторы MikroTik, Wi-Fi-точки доступа и другие устройства, поддерживающие клиентское VPN-подключение.

Сервер работает по модели *road warrior*: отдельные клиенты самостоятельно устанавливают соединение с VPN-сервером.

В текущей версии реализован VPN-сервер и подготовлены заготовки для Cloak-прокси. Полноценной частью проекта является только VPN-сервер.

## 3. Компоненты и возможности

### 3.1. VPN-сервер

Сервер поддерживает три способа подключения:

| Компонент | Протокол | Назначение |
|---|---|---|
| IPsec | IKEv2, strongSwan | Подключение клиентов по IPsec |
| OpenVPN `strong` | OpenVPN | Подключение с использованием более сильных алгоритмов |
| OpenVPN `compat` | OpenVPN | Совместимость с клиентами, имеющими ограниченную поддержку OpenVPN, в частности MikroTik RouterOS v6 |

Компоненты OpenVPN `strong`, OpenVPN `compat` и IPsec могут отключаться с помощью переменных окружения.

Каждый VPN-клиент проходит авторизацию с использованием клиентского сертификата. Для OpenVPN дополнительно предусмотрена авторизация по логину и паролю.

### 3.2. Внутренний DNS

Для всех подключённых клиентов ведётся общая DNS-зона. Имя клиента формируется на основе поля `CN` его сертификата.

При успешном подключении в DNS регистрируются записи:

- `A` — IPv4-адрес клиента;
- `AAAA` — IPv6-адрес клиента;
- `PTR` — обратное разрешение адреса.

При отключении клиента его записи удаляются.

DNS-сервер может пересылать запросы, которые не удалось разрешить в локальной зоне, другим DNS-серверам. Адреса серверов для пересылки задаются переменными окружения.

Таким образом, подключённые устройства могут обращаться друг к другу по DNS-именам, не используя IP-адреса напрямую.

#### Требования к CN клиентского сертификата

Поскольку поле `CN` используется для формирования DNS-имени, оно должно соответствовать допустимому формату DNS-имени.

Разрешены следующие символы:

- латинские буквы `A-Z` и `a-z`;
- цифры `0-9`;
- дефис `-`;

Каждая DNS-метка должна содержать от 1 до 63 символов. Дефис не может находиться в начале или конце метки.

Если в `CN` присутствуют недопустимые символы или нарушены требования к DNS-имени, регистрация клиента в DNS завершится ошибкой, после чего VPN-соединение с клиентом будет разорвано.

### 3.3. Веб-интерфейс

В проект входит простое веб-приложение на Flask. Через браузер можно посмотреть список подключённых клиентов, время и способ их подключения.

Данные для отображения берутся из локальной DNS-зоны. В частности, служебные TXT-записи содержат время и способ подключения клиента в кодировке Base64. Они используются веб-приложением и не предназначены для DNS-разрешения имён клиентами сети.

### 3.4. Поддержка IPv4 и IPv6

Клиентам может назначаться IPv6-адрес в дополнение к IPv4.

IPv4 является обязательным для OpenVPN: отключить его и оставить только IPv6 нельзя. Для strongSwan можно отключать и IPv4.
Поддержка IPv6 реализована, но протестирована не полностью.

### 3.5. Профили OpenVPN

Для OpenVPN предусмотрена система профилей, позволяющая назначать клиентам разные наборы сетевых настроек и правил межсетевого экрана.

Клиент передаёт логин и пароль вместе с сертификатом. Логин содержит имя пользователя и может содержать название профиля. Значения разделены запятой:

```text
username,profile
```

Имя пользователя всегда указывается первым. Оно используется для дополнительной авторизации по файлу `vpn/ovpn/users.list`. Если присутствует вторая часть логина, то она определяет профиль, назначаемый клиенту.

Профиль определяет:

- настройки OpenVPN, передаваемые клиенту при подключении, по аналогии с механизмом CCD;
- правила межсетевого экрана, применяемые на сервере для данного клиента.

Например, профиль `lan` может передавать клиенту маршруты к одной или нескольким приватным сетям. Если клиент сам выполняет функцию маршрутизатора, профиль также может содержать обратные маршруты. На сервере при этом устанавливаются правила, разрешающие обмен трафиком с указанными сетями.

Профиль `inet` может передавать клиенту маршрут по умолчанию, разрешать выход в интернет и включать NAT на сервере.

Таким образом, клиент может самостоятельно выбрать режим работы, указав соответствующий профиль в логине.

Если профиль не указан, дополнительные настройки и правила профиля не применяются. Клиент сможет обмениваться трафиком только с другими клиентами в своей VPN-подсети и не получит дополнительных OpenVPN-опций от сервера.

В этой версии отсутствует ограничение на выбор профиля в зависимости от сертификата. Любой клиент с действительными сертификатом, логином и паролем может запросить существующий на сервере профиль.

Дополнительно внутри профиля можно назначить индивидуальные настройки для конкретного клиента на основании `CN` его сертификата.

## 4. Развёртывание

Проект поставляется с Docker Compose-файлами, позволяющими запустить контейнер в нескольких сетевых режимах:

- **macvlan** — контейнер получает собственный IP-адрес в реальной VLAN локальной сети;
- **обычная сеть Docker** — контейнер работает в сети, созданной Docker;
- **host** — контейнер использует сетевой стек хоста.

Конкретный вариант выбирается с помощью соответствующего Compose-файла.

## 5. Переменные окружения

Переменные из файла `.env` используются в Docker Compose-файлах и, в зависимости от назначения, передаются в окружение запускаемого контейнера.

Исключение составляет `NET_IP_SERVER_VPN`: она используется только в Compose-файле для режима macvlan и задаёт IP-адрес VPN-сервера в сети macvlan.

### 5.1. Общие параметры

| Переменная | Пример | Описание |
|---|---|---|
| `SERVER_VPN_VERSION` | `1` | Тег образа `server_vpn`, используемый в Compose. Образ с этим тегом будет найден на локальном хосте или загружен из Docker Hub. |
| `NET_IP_SERVER_VPN` | `172.172.172.4` | IP-адрес VPN-сервера в macvlan сети. Используется только в Compose-файле для режима macvlan. |
| `VPN_DNS_ZONE` | `vpn` | Имя внутренней DNS-зоны, в которой регистрируются подключённые клиенты. Веб-интерфейс доступен по адресам `http://vpn` и `http://vpn.vpn`. |
| `PUBLIC_DNS4` | `8.8.8.8` | DNS-сервер IPv4, на который пересылаются запросы, не разрешённые в локальной зоне. Если переменная пустая, такие запросы не пересылаются и возвращают `NXDOMAIN`. |
| `PUBLIC_DNS6` | — | Аналогичный DNS-сервер для IPv6. |

### 5.2. Параметры OpenVPN

| Переменная | Пример | Описание |
|---|---|---|
| `PUBLIC_STRONG_PORT` | `1194` | TCP-порт, на котором принимает подключения OpenVPN-сервер `strong`. |
| `PUBLIC_COMPAT_PORT` | `1195` | TCP-порт, на котором принимает подключения OpenVPN-сервер `compat`. |
| `OVPN_STRONG_NET4` | `192.168.10.0/24` | Диапазон IPv4-адресов из которого клиенты OpenVPN `strong` получат адрес. Если переменная пустая, сервер `strong` не запускается. |
| `OVPN_COMPAT_NET4` | `192.168.11.0/24` | Диапазон IPv4-адресов из которого клиенты OpenVPN `compat` получат адрес. Если переменная пустая, сервер `strong` не запускается. |
| `OVPN_STRONG_NET6` | `fd7a:c506:d79a:1::/64` | Диапазон IPv6-адресов из которого клиенты OpenVPN `strong` получат адрес. Если переменная пустая, IPv6 в этом туннеле не используется. |
| `OVPN_COMPAT_NET6` | `fd7a:c506:d79a:2::/64` | Диапазон IPv6-адресов из которого клиенты OpenVPN `compat` получат адрес. Если переменная пустая, IPv6 в этом туннеле не используется. |

### 5.3. Параметры IPsec

| Переменная | Пример | Описание |
|---|---|---|
| `PUBLIC_DNS_NAME` | `vpn1.example.com` | DNS-имя IPsec-сервера, по которому его находят клиенты. Должно соответствовать имени в сертификате сервера. |
| `SWAN_SERVER_NET4` | `192.168.12.0/24` | Диапазон IPv4-адресов из которого клиенты strongSwan получат адрес. Если переменная пустая, IPv4 в IPsec-туннеле не используется. |
| `SWAN_SERVER_NET6` | `fd7a:c506:d79a:3::/64` | Диапазон IPv6-адресов из которого клиенты strongSwan получат адрес. Если переменная пустая, IPv6 в IPsec-туннеле не используется. |

Если обе переменные `SWAN_SERVER_NET4` и `SWAN_SERVER_NET6` пустые, strongSwan не запускается.

## 6. Файловая структура и данные

Структура каталогов позволяет выбирать способ сборки Docker-образов, хранения их резервных копий и подключения к Compose-проекту.

### 6.1. Сборка Docker-образов

Каталог `images/` содержит материалы для сборки Docker-образов.

Скрипты в этом каталоге позволяют вручную собрать образы и сохранить их копии в `images_backup/`. Такой способ удобен, например, при работе в сетях с ограниченным доступом к интернету или при необходимости самостоятельно контролировать резервные копии образов без использования Docker Hub. Скрипты сборки можно модифицировать под свои задачи, например добавить в них загрузку образа в Docker Hub.

Ручная сборка не обязательна: Docker Compose может использовать каталоги образов непосредственно в качестве контекста сборки.

### 6.2. Сертификаты и ключи: `pki/`

Каталог `pki/` монтируется в контейнер и содержит серверные сертификаты и ключи, необходимые для приёма клиентских подключений.

Ожидаемые файлы:

```text
pki/
├── ca.crt
├── crl.pem
├── server.crt
├── server.key
└── server.tc2
```

`server.tc2` — серверный ключ `tls-crypt-v2`, используемый конфигурацией OpenVPN `strong`. При запуске только конфигурации OpenVPN `compat` этот ключ можно не добавлять.

### 6.3. Файлы состояния OpenVPN: `stat/`

Каталог `stat/` монтируется в контейнер. В нём OpenVPN-серверы размещают файлы состояния:

```text
server-strong.status
server-compat.status
```

### 6.4. Настройки OpenVPN: `vpn/`

Каталог `vpn/` монтируется в контейнер и содержит общие настройки профилей для обоих OpenVPN-серверов.

Структура:

```text
vpn/
└── ovpn/
    ├── users.list
    └── profiles/
        ├── lan/
        │   ├── DEFAULT.conf
        │   ├── DEFAULT.fwl
        │   ├── client1.conf
        │   └── client1.fwl
        └── inet/
            ├── DEFAULT.conf
            └── DEFAULT.fwl
```

Названия каталогов `lan` и `inet` приведены в качестве примера.

Каталог `vpn/` читается при каждом подключении клиента. Поэтому настройки профилей можно изменять извне, без пересборки образа или перезапуска контейнера.

## 7. Авторизация и профили OpenVPN

### 7.1. Список пользователей: `vpn/ovpn/users.list`

Файл `vpn/ovpn/users.list` содержит список логинов и паролей, используемых при дополнительной авторизации OpenVPN-клиентов.

Каждая строка содержит два поля, разделённых пробелами:

```text
<username> <password>
```

Первое поле — имя, второе — пароль.

При обработке файла пробельные символы в начале и конце строки, а также между полями обрезаются. Строки, начинающиеся с `#`, считаются комментариями.

Вместо любого поля можно использовать `*`, обозначающую произвольное значение.

Например:

```text
* *
```

Такая запись разрешает произвольные логин и пароль. Её можно использовать, когда необходимо назначать профили, но дополнительная проверка логина и пароля не требуется.

При использовании профилей пользователь присылает логин вида:

```text
username,profile
```

В `vpn/ovpn/users.list` используется первая часть логина — `username`. Вторая часть определяет профиль OpenVPN.

### 7.2. Каталог профилей

В `vpn/ovpn/profiles/` находятся подкаталоги с настройками отдельных профилей. Имя подкаталога соответствует названию профиля, переданному клиентом в логине.

Каждый профиль содержит файлы двух типов:

- `.conf` — настройки OpenVPN, передаваемые клиенту;
- `.fwl` — правила межсетевого экрана, применяемые на сервере.

Имя файла соответствует `CN` клиентского сертификата.

Для каждого профиля могут использоваться индивидуальные файлы клиента и файлы настроек по умолчанию:

```text
profiles/
└── <profile>/
    ├── DEFAULT.conf
    ├── DEFAULT.fwl
    ├── <client-CN>.conf
    └── <client-CN>.fwl
```

Индивидуальные файлы выбираются независимо друг от друга:

- Если персональный `.conf` отсутствует, используется `DEFAULT.conf`.
- Если персональный `.fwl` отсутствует, используется `DEFAULT.fwl`.

Таким образом, для клиента можно задать только один персональный файл, а второй взять из настроек по умолчанию.

Если для одного из типов файлов отсутствуют и персональный файл, и соответствующий файл `DEFAULT`, клиент будет отключён.

В обоих типах файлов допускаются комментарии строк, начинающиеся с `#`.

### 7.3. Файлы `.conf`: настройки OpenVPN

Файлы `.conf` содержат директивы OpenVPN, аналогичные настройкам CCD. Дополнительно поддерживается подстановка шаблонных переменных.

Это позволяет использовать один и тот же файл профиля для обоих OpenVPN-серверов, даже если их адреса и DNS-параметры различаются.

Например:

```text
push "dhcp-option DOMAIN {{VPN_DOMAIN}}"
push "dhcp-option DNS {{VPN_SERVER_IP4}}"
push "dhcp-option DNS {{VPN_SERVER_IP6}}"
```

Поддерживаемые переменные:

| Переменная | Описание |
|---|---|
| `VPN_DOMAIN` | Имя внутренней DNS-зоны, в которой регистрируются клиенты. |
| `VPN_SERVER_IP4` | IPv4-адрес сервера в туннеле. |
| `VPN_SERVER_IP6` | IPv6-адрес сервера в туннеле. |

### 7.4. Файлы `.fwl`: правила межсетевого экрана

Файлы `.fwl` содержат упрощённые директивы для формирования правил межсетевого экрана на сервере.

Например, для профиля `lan` может потребоваться разрешить клиенту доступ к дополнительной приватной сети:

```text
ALLOWNET 192.168.2.0/24
```

Для профиля `inet` можно использовать следующий набор правил:

```text
NAT
ALLOWNET inet
```

Он включает маскарадинг исходящего трафика клиента и разрешает обмен со всеми адресами IPv4 и IPv6.

Поддерживаемые директивы:

| Директива | Описание |
|---|---|
| `NAT` | Маскарадинг всего трафика от клиента. |
| `NAT4` | Маскарадинг только IPv4-трафика от клиента. |
| `NAT6` | Маскарадинг только IPv6-трафика от клиента. |
| `ALLOWNET NET` | Разрешает двусторонний обмен трафиком клиента с сетью `NET`. |

В качестве `NET` можно указать адресную сеть в формате `net/len` (IPv4 или IPv6) либо специальное значение `inet`, которое обозначает весь диапазон адресов обоих семейств: `0.0.0.0/0` и `::/0`.
